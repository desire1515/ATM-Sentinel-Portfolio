01 / THE CHALLENGE

When a transaction
breaks the pattern.

ATM networks process many transactions, and most follow familiar patterns. A transaction that differs from those patterns can be difficult to spot by scanning records one by one.

This project explores an analytical approach: process transaction data, identify records that appear unusual, then present those records for human review. The goal is to support investigation and learning — not to make automatic decisions about customers or claim that an alert proves wrongdoing.

!

Important distinction
An anomaly means a transaction looks unusual in the data. It does not, by itself, mean fraud.

02 / PROJECT DIRECTION

From raw records
to useful review.

The aim is to develop an academic prototype that applies anomaly-detection techniques to synthetic ATM transactions and presents the resulting alerts in an understandable dashboard.

SPECIFIC OBJECTIVES

01 — 04
01

Prepare transaction data

Use Python data-processing tools to organize a synthetic ATM transaction dataset for analysis.

02

Identify unusual activity

Apply Isolation Forest to surface records that differ from the patterns learned by the model.

03

Make results reviewable

Present transactions, analytics and model outputs through a React-based dashboard.

04

Communicate limitations

Keep the synthetic-data context clear and distinguish unusual behaviour from confirmed fraud.
